# Crypto Price Tracker API

REST API для управления списком криптовалют и хранения истории котировок CoinMarketCap. Все цены сохраняются и возвращаются в USD. Данные приложения находятся в SQLite, доступ к таблицам реализован raw SQL через `better-sqlite3` без ORM. Работа с базой изолирована в `worker_threads`, поэтому синхронные SQLite-вызовы не блокируют Event Loop HTTP-процесса.

Схема использует первичные и внешние ключи, ограничения `NOT NULL`, `UNIQUE` и `CHECK`, а время хранится в ISO 8601. SQL выполняется подготовленными запросами с параметрами. Запись котировок и времени обновления выполняется атомарной транзакцией; для блокировок настроено ожидание до 5 секунд и до двух повторов безопасных чтений. Если база остаётся заблокированной, API возвращает `503`.

Код разделён на HTTP-слой, application ports, сервис синхронизации, инфраструктурные адаптеры SQLite/CoinMarketCap и конфигурацию. Сервис зависит от интерфейсов хранилища и провайдера котировок; реальные реализации подключаются в composition root `src/server.ts`.

## Требования

- Node.js 18+ и npm
- API key CoinMarketCap
- Секретный `API_KEY` для авторизации клиентов

SQLite-драйвер `better-sqlite3` — нативный модуль. Если для вашей версии Node нет готового бинарного пакета, для локальной установки нужны инструменты C/C++; запуск через Docker использует Node 20 и собирает драйвер внутри Linux-образа.

## Запуск локально

```sh
npm ci
cp .env.example .env
```

Укажите в `.env` `CMC_API_KEY` и `API_KEY` (не менее 16 символов), затем:

```sh
npm run build
npm start
```

При первом старте SQLite-файл и каталог создаются автоматически. По умолчанию файл находится в `data/prices.sqlite`, эта директория исключена из Git.

`CMC_BASE_URL`, `CMC_TIMEOUT_MS`, `SYNC_INTERVAL_MS`, `PORT`, `DATABASE_PATH` и `LOG_LEVEL` в примере уже заполнены значениями по умолчанию. `READ_API_KEY` можно задать отдельно, если нужен ключ только для чтения.

## Docker

Скопируйте `.env.example` в `.env`, задайте оба ключа и выполните:

```sh
docker compose up --build -d
```

База хранится в именованном Docker volume `crypto-data`.

## Авторизация

Все маршруты `/api/*` требуют Bearer-заголовок:

```http
Authorization: Bearer <API_KEY или READ_API_KEY>
```

`API_KEY` разрешает чтение и изменение данных. Для клиентов, которым нужно только чтение, можно задать отдельный `READ_API_KEY`; он разрешает безопасные read-запросы, а для изменений возвращается `403`. Оба ключа должны быть не короче 16 символов и различаться.

CoinMarketCap key передаётся только серверу через `CMC_API_KEY`, в клиентские ответы не попадает. Вызовы CMC имеют таймаут (`CMC_TIMEOUT_MS`, по умолчанию 5 секунд) и до двух повторов с экспоненциальной задержкой при сетевых сбоях, `429` и `5xx`. Ошибка ручной синхронизации возвращает `502`; фоновая задача пишет ошибку в лог и продолжает следующие циклы. При завершении SIGINT/SIGTERM таймер останавливается, активный запрос синхронизации дожидается завершения, затем закрываются worker и база.

Каждый HTTP-запрос получает UUID в заголовке `X-Request-Id`. Запросы и ошибки журналируются в JSON с уровнями `error`, `warn`, `info`; уровень задаётся через `LOG_LEVEL`. Ошибочные ответы содержат `statusCode`, `timestamp`, `requestId` и при необходимости безопасный `context`.

## API

Интерактивный Swagger UI не включён, чтобы не добавлять неуказанные runtime-зависимости. Спецификация OpenAPI 3.0 находится в [`openapi.yaml`](./openapi.yaml) и может быть загружена в Swagger Editor/UI.

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Проверка сервиса (без авторизации) |
| `GET /status` | Проверка сервиса (без авторизации, alias для health check) |
| `GET /api/cryptocurrencies` | Список отслеживаемых валют |
| `POST /api/cryptocurrencies` | Добавить `{ "symbol": "BTC", "name": "Bitcoin" }` |
| `GET /api/cryptocurrencies/:id` | Получить запись |
| `PUT /api/cryptocurrencies/:id` | Обновить `symbol` и `name` |
| `DELETE /api/cryptocurrencies/:id` | Удалить валюту и её историю |
| `GET /api/prices` | Последняя сохранённая цена каждой валюты |
| `GET /api/cryptocurrencies/:id/history?limit=100&from=...&to=...` | История цен, от новых к старым |
| `POST /api/sync` | Запустить синхронизацию немедленно |

Фоновая синхронизация запускается при старте, затем выполняется с интервалом `SYNC_INTERVAL_MS` (по умолчанию 60 секунд после завершения предыдущего цикла). Планировщик не ставит повторные запуски в очередь; одновременные ручной и фоновой вызовы используют одну синхронизацию. Успешные и неуспешные фоновые запуски журналируются. Символы передаются в CMC пакетно; ответ API содержит число обновлённых валют и символы, для которых котировка отсутствует.

Ограничения валидации: символ — 2–12 латинских букв/цифр; имя — 1–100 символов; `limit` истории — 1–1000; `from` и `to` — ISO 8601. Неизвестные параметры истории и тело запроса к `/api/sync` отклоняются. Повторный символ отвечает `409`, несуществующая запись — `404`, ошибка входных данных — `400`.

## Тесты

```sh
npm test
```

Или собрать тестовую стадию в Docker:

```sh
docker build --target test -t crypto-price-tracker:test .
```

Тесты используют SQLite in-memory и тестовый локальный HTTP-сервер вместо настоящего CoinMarketCap; реальный ключ не нужен. Проверяются положительные и отрицательные сценарии маршрутов, заголовок CMC API key, таймаут и ошибки upstream, планировщик, миграция схемы и остановка фоновой синхронизации.
